# data-ownership Specification

## Purpose

У каждого пользователя свои контакты, заметки и группы. Человек видит и меняет только своё. Чужое для него не существует: ни на экранах, ни при прямых запросах к серверу.

## Requirements

### Requirement: У контакта и группы есть владелец

Каждый контакт и каждая группа SHALL принадлежать одному пользователю: тому, кто их создал. Заметки принадлежат владельцу контакта. Владелец не меняется.

#### Scenario: Добавил контакт
- **WHEN** пользователь A добавил контакт «Фёдор»
- **THEN** «Фёдор» есть в списке A

#### Scenario: Создал группу
- **WHEN** пользователь A создал группу «Дача» в карточке своего контакта
- **THEN** «Дача» есть в группах A

### Requirement: Список и поиск - только свои контакты

Список контактов, поиск, подписи с числом контактов и пустой список SHALL учитывать только контакты вошедшего пользователя.

#### Scenario: Контакт A не виден B
- **WHEN** A вошёл и добавил контакт «Фёдор Проверкин», потом вошёл B
- **THEN** в списке B нет «Фёдора Проверкина»
- **AND** поиск B по «Проверкин» ничего не находит

#### Scenario: Число контактов
- **WHEN** у A 3 контакта, у B 5
- **THEN** B видит «Всего 5 контактов»

### Requirement: Чужой контакт по прямой ссылке не найден

Карточка и страница изменения контакта SHALL показывать «Контакт не найден» и кнопку «К списку контактов», если контакт принадлежит другому пользователю. Несуществующий контакт показывает ту же страницу: по ответу нельзя понять, что контакт есть у кого-то другого.

#### Scenario: Чужая карточка
- **WHEN** B открыл адрес карточки контакта A
- **THEN** видно «Контакт не найден» и кнопка «К списку контактов», данных контакта A на странице нет

#### Scenario: Чужая страница изменения
- **WHEN** B открыл адрес страницы изменения контакта A
- **THEN** видно «Контакт не найден», формы с данными A нет

#### Scenario: Несуществующий контакт
- **WHEN** пользователь открыл адрес карточки с номером, которого нет ни у кого
- **THEN** видна та же страница «Контакт не найден», что и для чужого контакта

### Requirement: Чужой контакт не меняется прямым запросом

Сервер SHALL проверять владельца при каждом изменении. Запрос с номером чужого контакта MUST ничего не менять: ни сам контакт, ни заметки, ни частоту общения, ни группы. Ответ такой же, как для несуществующего контакта.

#### Scenario: Заметка к чужому контакту
- **WHEN** B отправил на сервер новую заметку с номером контакта A
- **THEN** ответ «Контакт не найден», у контакта A новой заметки нет

#### Scenario: Изменение чужого контакта
- **WHEN** B отправил на сервер изменение контакта A
- **THEN** ответ «Контакт не найден», контакт A не изменился

#### Scenario: Удаление чужого контакта
- **WHEN** B отправил на сервер удаление контакта A
- **THEN** контакт A и его заметки на месте

#### Scenario: Частота чужого контакта
- **WHEN** B отправил на сервер «Раз в неделю» для контакта A
- **THEN** ответ «Контакт не найден», частота контакта A не изменилась

#### Scenario: Группа у чужого контакта
- **WHEN** B отправил на сервер «добавить в группу» или «новая группа» для контакта A
- **THEN** ответ «Контакт не найден», группы контакта A не изменились, новой группы нет

### Requirement: У каждого свои группы

Группы в карточке, ряд фильтра на главной и страница «Группы» SHALL показывать только группы вошедшего пользователя. Число контактов у группы считается по его контактам. Сервер MUST не давать переименовать, удалить или отметить чужую группу.

#### Scenario: Группы B не видны A
- **WHEN** у B есть группа «Дача», у A её нет
- **THEN** у A нет «Дачи» ни в карточке, ни в фильтре, ни на странице «Группы»

#### Scenario: Чужая группа в адресе
- **WHEN** A открыл главную с номером группы B в адресе
- **THEN** выбрано «Все», видны все контакты A, как для группы, которой нет

#### Scenario: Свой контакт в чужую группу
- **WHEN** A отправил на сервер «добавить своего контакта в группу B»
- **THEN** ответ «Группа не найдена», состав группы B не изменился

#### Scenario: Переименование и удаление чужой группы
- **WHEN** A отправил на сервер переименование или удаление группы B
- **THEN** ответ «Группа не найдена» или ничего, группа B не изменилась и не удалена

### Requirement: «Пора связаться» - только свои

Блок «Пора связаться» SHALL показывать только контакты вошедшего пользователя.

#### Scenario: Срок у контакта A
- **WHEN** у контакта A срок связаться наступил, а у контактов B нет
- **THEN** у B на главной нет блока «Пора связаться»

### Requirement: Новый пользователь начинает с пустого списка

Пользователь, который вошёл первый раз, SHALL видеть пустой список с подсказкой добавить первый контакт: «Пока нет ни одного контакта» и кнопку «Добавь первый контакт». Групп у него нет.

#### Scenario: Первый вход
- **WHEN** в приложении есть контакты A, и B вошёл первый раз
- **THEN** B видит «Пока нет ни одного контакта» и кнопку «Добавь первый контакт»
- **AND** на главной нет ряда фильтра по группам

### Requirement: Без входа сервер не отдаёт и не меняет данные

Запрос к серверу без входа SHALL не получать ни одного контакта, заметки или группы и MUST ничего не менять, даже если он пришёл не из интерфейса.

#### Scenario: Изменение без входа
- **WHEN** запрос «добавить заметку» с номером существующего контакта пришёл на сервер без входа
- **THEN** заметка не добавлена, в ответе нет данных контакта

### Requirement: Существующие данные переходят к владельцу

При обновлении до версии со входом все контакты, заметки и группы, которые уже есть в базе, SHALL перейти к пользователю с почтой владельца из настроек сервера. Ни одна запись MUST не теряться и не меняться. Если данные есть, а почта владельца не задана, обновление MUST остановиться до запуска новой версии, ничего не изменив.

#### Scenario: Обновление с данными
- **WHEN** в базе 1000 контактов, 2500 заметок и 5 групп, почта владельца задана, и приложение обновили
- **THEN** контактов, заметок и групп столько же, их поля и состав групп прежние
- **AND** все они принадлежат пользователю с почтой владельца

#### Scenario: Владелец вошёл после обновления
- **WHEN** владелец вошёл по ссылке на свою почту
- **THEN** он видит все контакты, заметки и группы, которые были до обновления

#### Scenario: Почта владельца не задана
- **WHEN** в базе есть контакты, а почта владельца в настройках не задана, и запустили обновление
- **THEN** обновление остановилось с понятной ошибкой, база не изменилась

#### Scenario: Пустая база
- **WHEN** в базе нет данных, почта владельца не задана, и запустили обновление
- **THEN** обновление прошло, пользователей нет

### Requirement: Демо-данные у владельца

Демо-данные для проверки SHALL создаваться у пользователя с почтой владельца из настроек.

#### Scenario: Заполнил пустую базу демо-данными
- **WHEN** в пустую базу загрузили демо-данные
- **THEN** все демо-контакты, заметки и группы принадлежат пользователю с почтой владельца
