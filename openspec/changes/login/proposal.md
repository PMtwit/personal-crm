# Proposal

## Why

Приложением хотят пользоваться друзья, но сейчас контакты общие: любой, кто откроет https://app.pmcrm.site, видит и меняет одни и те же данные. Нужно, чтобы каждый входил под своей почтой и вёл только свои контакты, а чужие не видел. Требования - `specs/02-пользователи-вход.md`.

## What Changes

- **BREAKING** Без входа приложение не открывается. Любая страница без входа ведёт на страницу входа. Открытыми остаются только сама страница входа, `/health` для проверки выкатки и картинка для превью ссылки.
- Страница входа: только поле «Почта» и кнопка «Получить ссылку», без заголовка. Паролей нет. Первый вход по ссылке и есть регистрация, имя не спрашиваем.
- Письмо «Вход в Личную CRM» от «Личная CRM» `noreply@mail.crm.pmcrm.site` с кнопкой «Войти». Ссылка работает один раз и 15 минут. Новая ссылка отменяет старые. Не больше 3 писем на одну почту за 10 минут.
- Почту проверяет сервер: пробелы по краям убираются, большие и маленькие буквы не различаются, неверный адрес - «Проверь адрес почты». После отправки всегда «Ссылка для входа отправлена на <почта>», чтобы не выдавать, есть ли такой пользователь.
- Старая или использованная ссылка - «Ссылка устарела, запроси новую» и кнопка «Получить новую ссылку» на страницу входа. Если письмо не отправилось - «Не получилось отправить письмо, попробуй ещё раз».
- Вход держится 30 дней с последнего захода на устройстве. Можно войти с нескольких устройств. В шапке - почта и «Выйти». Выход действует только на этом устройстве.
- У каждого контакта и группы есть владелец. Пользователь видит и меняет только своё: список, поиск, карточку, заметки, группы, фильтр, «Пора связаться». Чужое не открывается ни в интерфейсе, ни прямым запросом к серверу. Чужой контакт по прямой ссылке - «Контакт не найден» и кнопка «К списку контактов».
- Новый пользователь начинает с пустого списка. Кнопка на пустом списке теперь «Добавь первый контакт», как в спеке, вместо «Добавить первый контакт»; надпись «Пока нет ни одного контакта» прежняя.
- Названия групп уникальны у каждого пользователя свои: у A и у B может быть по группе «Друзья».
- **BREAKING** Несуществующий контакт по прямой ссылке теперь тоже показывает «Контакт не найден», а не «Такой страницы нет». Иначе по разнице текстов можно было бы понять, что чужой контакт существует.
- Все контакты, заметки и группы, которые уже есть в базе, при выкатке переходят к владельцу. Его почта берётся из настройки `OWNER_EMAIL` в `.env`, не из кода: репозиторий публичный. Ни одна запись не теряется. Демо-данные (`db:seed`) тоже создаются у владельца.
- Письма отправляет Nodemailer. Куда они уходят, решает настройка, а не код. На компьютере и в автотестах письма попадают в заглушку Mailpit в Docker, на сервере уходят по-настоящему через Resend.

Вне рамок: пароли, вход через Google и соцсети, код из письма, профиль и смена почты, удаление аккаунта, общий доступ к контактам, приглашения, роли и админка.

## Capabilities

### New Capabilities

- `user-auth`: вход по ссылке из письма. Страница входа, проверка почты, письмо, срок и одноразовость ссылки, лимит писем, сессия на 30 дней, выход, куда уходят письма.
- `data-ownership`: у каждого пользователя свои данные. Владелец у контактов и групп, видно и меняется только своё, чужое не открывается прямым запросом, существующие данные переходят к владельцу.

### Modified Capabilities

- `contact-groups`: название группы не повторяется у одного пользователя. У разных пользователей названия могут совпадать.

## Impact

- База: таблицы входа Better Auth `users`, `sessions`, `accounts`, `verifications`. Таблица `sign_in_emails` для лимита писем. Колонка `user_id` у `contacts` и `groups`. Уникальность названия группы - в пределах пользователя. Миграция `drizzle/0003_*.sql` **меняет существующие данные**: проставляет владельца всем контактам и группам. По правилам проекта её надо показать владельцу до merge.
- Код: `src/db/schema.ts`; `src/lib/data.ts`: каждая функция принимает `userId` и отдаёт только данные этого пользователя; `src/app/actions.ts`: каждое действие берёт пользователя из сессии. Добавляются: настройка Better Auth (`src/lib/auth.ts`), отправка писем (`src/lib/mail.ts`), `src/proxy.ts` для перехода на страницу входа, страница входа и страница «Ссылка устарела», шапка с почтой и «Выйти», страница «Контакт не найден» для карточки. В `src/components/contact-list.tsx` меняется текст кнопки пустого списка.
- Скрипты: `scripts/migrate.mts` передаёт `OWNER_EMAIL` миграции, `scripts/seed.mts` создаёт данные у владельца. `pnpm db:migrate` запускает тот же скрипт, что и сервер.
- Зависимости: `better-auth`, `nodemailer` и для разработки `@types/nodemailer`. Better Auth и Mailpit есть в стеке в CLAUDE.md, Nodemailer и Resend названы в спеке. Других новых библиотек и сервисов нет.
- Docker: Mailpit в `compose.yaml` для компьютера, Mailpit в CI для Vitest и Playwright.
- Тесты: Vitest для правил входа и разделения данных. Отдельный e2e входа. Существующие e2e сначала входят под тестовым пользователем. В двух e2e ожидаемый текст «Такой страницы нет» для несуществующего контакта меняется на «Контакт не найден».
- Выкатка: в `.env` на сервере появляются строки `BETTER_AUTH_SECRET`, `SMTP_URL` с ключом Resend и `OWNER_EMAIL`. `deploy/compose.yaml` передаёт их приложению и миграциям. Без них выкатка остановится до бэкапа, и прежняя версия продолжит работать. Откат после выкатки - только вместе: прошлая версия и база из бэкапа, по разделу README «Вернуть и версию, и базу».
- Только человек: аккаунт Resend, записи DNS для `mail.crm.pmcrm.site`, ключ Resend и строки в `.env`.
- README: вход, Mailpit, новые строки `.env`. Убрать фразу «Входа в приложении нет».
