# Личная CRM

Приложение, где я веду контакты людей, которых знаю лично: кто это, откуда знакомы, телефон и почта, о чём договорились. Идея и главный сценарий — в [specs/01-продуктовая-идея.md](specs/01-продуктовая-идея.md).

## Что нужно установить

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) — в нём работает база данных
- Node.js 24 (LTS) и pnpm — ставятся через Homebrew:

  ```
  brew install node@24 pnpm
  ```

## Первый запуск базы данных

1. Создайте файл настроек из шаблона:

   ```
   cp .env.example .env
   ```

2. Откройте `.env` и заполните значения. Пароль можно сгенерировать командой `openssl rand -hex 24`. В `DATABASE_URL` подставьте те же имя пользователя, пароль и имя базы.

3. Запустите базу:

   ```
   docker compose up -d --wait
   ```

## Проверить, что база работает

```
docker compose ps
```

У `personal-crm-db-1` должен быть статус `(healthy)` и адрес `127.0.0.1:5432`.

Подключиться к базе и узнать её версию:

```
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "select version();"'
```

## Остановить и запустить снова

- Остановить: `docker compose stop`
- Запустить: `docker compose up -d --wait`

База запускается сама вместе с Docker Desktop.

## Важно про данные

- Все контакты хранятся внутри Docker, в томе `personal-crm_pgdata`
- `docker compose down -v` **удаляет все данные без возможности восстановления**. Обычные `docker compose stop` и `docker compose down` данные не трогают
- База доступна только с этого компьютера — из локальной сети к ней подключиться нельзя
- `.env` с паролем не попадает в git. В git лежит только `.env.example` без значений

## Приложение

### Первый запуск

Все команды — в папке проекта, база должна быть запущена (см. выше).

1. Установить библиотеки:

   ```
   pnpm install
   ```

2. Создать таблицы в базе:

   ```
   pnpm db:migrate
   ```

3. Наполнить базу тестовыми данными — 1000 вымышленных контактов с заметками (по желанию):

   ```
   pnpm db:seed
   ```

   Команда срабатывает только на пустой базе. Если в ней уже есть хотя бы один контакт, она ничего не добавит и ничего не изменит. Почты у тестовых контактов — на служебных доменах `example.com`, `example.org`, `example.net`, поэтому письмо по ним никуда не уйдёт.

### Запустить

```
pnpm build
pnpm start
```

Откройте в браузере http://localhost:3000. Остановить — `Ctrl+C` в окне терминала, где запущено приложение.

`pnpm build` нужен после каждого обновления кода. Если вы меняете код и хотите сразу видеть изменения, вместо этих двух команд запустите `pnpm dev`: так удобнее разрабатывать, но приложение работает медленнее.

Приложение открывается только на этом компьютере: из локальной сети, например с телефона, его не видно. Входа по паролю в приложении нет, поэтому так безопаснее.

### Что умеет

- Главная страница — все контакты по алфавиту, с разбивкой по буквам
- Поиск по имени — список фильтруется во время набора. Регистр не важен, «ё» и «е» считаются одной буквой, слова можно вводить в любом порядке: «петров иван» найдёт «Иван Петров»
- «Добавить контакт» — имя (обязательно), кто это, откуда знакомы, телефон, почта
- Карточка контакта — все поля, кнопка «Изменить» и заметки. Новая заметка сохраняется кнопкой «Добавить заметку» или сочетанием ⌘ + Enter. Каждая заметка хранится отдельно, с датой и временем, новые — сверху

### Превью ссылки

Когда ссылку на приложение отправляют в мессенджер или соцсеть, показывается карточка: заголовок «Не теряйте людей, которых знаете лично», описание и картинка. Тексты и картинка те же, что у лендинга. Превью одинаковое для любой страницы приложения, имена контактов в него не попадают.

- Тексты — в `src/app/layout.tsx`, блок `openGraph`
- Картинка — `src/app/opengraph-image.png`, копия `public/og-image.png` из репозитория лендинга. Если картинку на лендинге перерисовали, скопируйте новую сюда под тем же именем
- Подпись к картинке для незрячих — `src/app/opengraph-image.alt.txt`

Мессенджеры запоминают превью. Если после выкатки видна старая карточка, в Telegram её можно обновить через бота `@WebpageBot`: отправьте ему ссылку.

### Проверить, что всё работает

Автотест проходит главный сценарий из спеки: открыть список → добавить контакт → найти по имени → дописать заметку → проверить, что всё сохранилось, в том числе при открытии в другом браузере.

```
pnpm test:e2e
```

Тест работает с отдельной базой `personal_crm_test` и запускает своё приложение на порту 3100, поэтому ваши контакты не трогает и запущенному приложению не мешает. Для теста нужен установленный Google Chrome. При каждом запуске тестовая база очищается и заполняется заново.

### Если что-то пошло не так

- На странице «Не получилось загрузить данные» — не запущена база. Откройте Docker Desktop и выполните `docker compose up -d --wait`
- `Port 3000 is in use` — приложение уже запущено в другом окне терминала. Откройте http://localhost:3000 или остановите то приложение

## Выкатка на сервер

Приложение работает на https://app.pmcrm.site. Новая версия выкатывается сама после каждого push в `main`.

Входа в приложении нет, поэтому на сервере контакты может смотреть и менять любой, кто знает адрес. Пока там только тестовые данные, так решено оставить (25.10.2026). Поисковикам страницы закрыты заголовком `noindex`.

### Как это устроено

1. GitHub Actions (workflow «Deploy», `.github/workflows/deploy.yml`) собирает образ приложения и кладёт его в GHCR. Тег образа — SHA коммита
2. Копирует на сервер `deploy/compose.yaml` и `deploy/deploy.sh` и запускает `deploy.sh`
3. `deploy.sh` на сервере: скачивает образ → разовым контейнером из этого образа применяет миграции → запускает новую версию → проверяет `/health`
4. Workflow ещё раз проверяет https://app.pmcrm.site/health снаружи, через nginx

Если миграции упали, новая версия не запускается, продолжает работать прежняя. Если проверка `/health` красная, выкатка считается упавшей. Сам ничего не откатывается: откат запускается только вручную (см. ниже).

После удачной выкатки на сервере остаются только два образа приложения: текущий и предыдущий.

### Что где на сервере

- Папка `/srv/personal-crm`: `compose.yaml`, `deploy.sh`, `.env`. Файлы `deployed-tag` и `previous-tag` хранят SHA текущей и предыдущей версий
- Пользователь `deploy` нужен только для выкатки: он может запускать Docker, sudo у него нет. Его ключ лежит в секрете GitHub `DEPLOY_SSH_KEY`
- Проект docker compose `prod`: `db` — PostgreSQL (данные в томе `prod_pgdata`), `app` — приложение (слушает только 127.0.0.1:3000), `migrate` — разовый контейнер для миграций
- nginx отдаёт приложение по адресу app.pmcrm.site. Его конфиг лежит в `deploy/nginx/app.pmcrm.site.conf` и поставлен на сервер вручную, выкатка nginx не меняет

### .env на сервере

Файл `/srv/personal-crm/.env`, права 600. В нём три строки:

```
POSTGRES_USER=crm
POSTGRES_PASSWORD=пароль
POSTGRES_DB=crm
```

Пароль можно сгенерировать командой `openssl rand -hex 24`. Адрес базы для приложения `compose.yaml` собирает из этих строк сам.

Создать или изменить файл:

```
ssh crm
sudo -u deploy bash -c 'umask 077 && nano /srv/personal-crm/.env'
```

Пароль базы применяется только при самом первом запуске, когда база создаётся. Если потом поменять его только в `.env`, приложение не сможет подключиться: сначала пароль меняют в самой базе.

### Выкатить новую версию

Влейте изменения в `main`, например смёржите pull request. Ход выкатки виден на GitHub во вкладке Actions, выкатка идёт 3–5 минут.

### Проверить, что работает

- https://app.pmcrm.site/health отвечает `{"status":"ok"}`
- Какая версия запущена и в каком состоянии: `ssh crm docker ps`, в колонке IMAGE видно SHA коммита
- Логи приложения: `ssh crm docker logs --tail 100 prod-app-1`
- Если на сайте страница «Не получилось загрузить данные», откройте https://app.pmcrm.site/health. Ответ `database unreachable` значит, что приложение не достаёт до базы: проверьте `ssh crm docker ps`, у `prod-db-1` должен быть статус `(healthy)`

### Откатить на предыдущую версию

Откат запускаете только вы:

```
ssh crm
sudo -u deploy cat /srv/personal-crm/previous-tag
sudo -u deploy /srv/personal-crm/deploy.sh SHA_из_предыдущей_команды
```

Миграции при откате не отменяются. Если новая версия меняла таблицы, старая может с ними не заработать: перед таким откатом проверьте, какие миграции были в новой версии.

Откатить на версию старше предыдущей: GitHub → Actions → Deploy → запуск с нужным коммитом → Re-run all jobs.

### Тестовые данные на сервере

1000 вымышленных контактов, как у `pnpm db:seed`. Срабатывает только на пустой базе:

```
ssh crm
sudo -u deploy bash -c 'cd /srv/personal-crm && APP_TAG=$(cat deployed-tag) docker compose -p prod run --rm -T migrate node scripts/seed.mts'
```
